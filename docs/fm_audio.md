# FM player sound checkpoint

The PCM device now consumes reconstructed OPL sound, with no WAV/OGG playback
or General MIDI substitution. The 39 executable-resident ten-byte patches are
provenance-labelled constants generated by `tools/generate_fm_reference.py`.
Runtime still needs only the original packs, not the unpacked executable or
analysis exports.

`fm_driver` translates 1121, 10F4, 0F0A and the nonspatial part of 39A9:
operator register offsets, patch caching, pitch division and block arithmetic,
carrier attenuation, retrigger and key release. A single driver owns nine voice
caches. 1,024 sequenced native comparisons check every emitted register byte,
including the effect of previous calls on cached writes.

`fm_synth` uses Nuked OPL3 at commit
`765ec962e473aeb767e4cba74ffdc8f588ffbfe8`, fetched from GitHub with a verified
archive hash. This is the same OPL2-compatible setup used for the independent
sound auditions. One-second Caero and boost PCM hashes match those native-register
auditions exactly, through the float output conversion. There is no added DC
filter, loudness normalisation or resampled audio file.

`fm_stream` transfers immutable voice snapshots over a Boost single-producer,
single-consumer queue. Only the audio thread touches the chip and voice caches;
it does not advance game state. The callback does not allocate or acquire locks.
Its queue has 128 frames; publication returns false if full. The current host
retries through subsequent state snapshots rather than blocking gameplay.
Very short events can be lost under prolonged consumer starvation; precise
sample-time scheduling remains future work with the complete audio allocator.

## Connected player effects

- Engine: Caero 3980 and Skimma 3914/391D, using the original definition's patch
  and pitch. The cockpit-hidden player branch supplies level 8800. Skimma pitch
  includes speed and the original clock/player-ID modulation; its extra
  object-specific modulation byte is zero at the current checkpoint. 512 native
  callback comparisons cover both craft, speeds, clocks and engine/crash gates.
- Boost: record 3792, patch 2, pitch 686, level B000, duration 1056 ticks.
- Full recharge pip: 37CE, patch 32, pitch 1372, level EE00, 640 ticks.
- Engine/shield switch acknowledgement: 38AA/38D2, 112 ticks.
- Shield start: B8E7 modifies 38FA to pitch 0302, duration 4080 ticks.
  The HUD-ready producer switches it to pitch 0362, duration 288 ticks.
  Disabling shields suppresses that record, as callback 390E requires.

These use capped game-clock deadlines, not a fixed-duration looping sample.
`--mute` avoids opening the audio device. Device failure leaves the application
runnable with a diagnostic. The device is destroyed before its stream state.
Checkpoint retry releases old voices before publishing the new player state.

## Limits and remaining work

The chip/register layer is reference-checked; the complete game's sound scene
is not yet reproduced. This checkpoint assigns engine and player effects to
fixed channels 0–4. Original priority ordering, competing world voices,
distance attenuation, stereo panning and Doppler remain to be connected. In
particular, the boost currently uses its stored level through the nonspatial
path, not the original spatial admission path. Camera-dependent engine level
will need to follow the camera system when external views are integrated.
Music and all five hardware arrangements are still separate work.
